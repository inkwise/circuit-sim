# CircuitLab / 电路实验室

一个在 Android 上离线运行的 C++ 电路仿真实验项目：

- **UI**：SDL3 3.4.18 + Dear ImGui 1.92.8，手机横屏、触屏、中文界面。
- **仿真引擎**：ngspice 47，以 `libngspice.so` 形式通过共享库 C API 集成。
- **功能**：工程管理、图形化电路编辑、直流工作点（OP）、瞬态分析（TRAN）、
  节点电压、支路/引脚电流、电子流动画、波形图、网表预览、日志、自动保存。
- **元件**：基础无源件、二极管/LED/稳压管、NPN/PNP 三极管、N-MOS、运放、
  555 定时器、AND/OR/NOT 逻辑门、7805 稳压器；以及开关电源所需的一套：
  PWM 信号源（占空比可调）、功率 N-MOS/P-MOS、肖特基二极管、功率电感（含 DCR）、
  电解电容（含 ESR）、示波器探头、2 脚接线端子；另外还有两片半导体制冷片
  （TEC1-12706 / TEC1-12710），带真实的电热耦合模型，会自己降温；
  以及真实板子上常见的几种器件：**IRL540N**（逻辑电平功率 N-MOS）、
  **陶瓷电容**（MLCC，含 ESR 与 ESL）、**功率电阻**（绕线/水泥电阻，含绕线电感和
  额定功率，超功率会烧断）。
- **仪器**：示波器元件 + “示波”结果页，直接给出平均值、峰峰纹波、纹波占比、
  有效值和开关频率。
- **目标 ABI**：`arm64-v8a`（Android 26+）。

- APK 可直接侧载测试。

## 构建

需要：Android SDK（platform 35、build-tools 34）、NDK 29、CMake、JDK 17；Termux 下已具备。

```bash
cd circuit-sim

# 1. 准备 SDL3 / ImGui / ngspice 47 / 字体 / Gradle wrapper
bash scripts/fetch-deps.sh

# 2. 交叉编译 ngspice（首次在手机上可能需要数分钟到十几分钟）
bash scripts/build-ngspice-android.sh

# 3. 编译并运行 core/ngspice 验收测试
bash scripts/run-engine-tests.sh

# 4. 构建并暂存 APK
bash scripts/build-apk.sh
```

APK 输出：

```
dist/CircuitLab-0.2.0-debug.apk
```

装完可以到 **顶部菜单 → 设置** 最下面确认：`版本 0.2.0 · 构建 <编译时间>`，
以及 `元件库 35 种（晶体管 6 种）`。这两个数字对不上就说明手机上还是旧包。

## 安装

```bash
bash scripts/install-apk.sh
# 等价于：
termux-open --content-type application/vnd.android.package-archive \
  dist/CircuitLab-0.2.0-debug.apk
```

设备需要允许“安装未知应用”。

## 使用

### 首页与工程

- 首页列出 **工程**，按修改时间排序，可 **新建 / 编辑 / 删除**。
- “新建工程”会弹出名称输入框；创建后进入绘制页。
- **首次启动会自动加入一个示例工程**“MOS 开关板示例”，出现在“我的工程”列表里，
  点开即自动开始仿真并直接打开结果面板（这套板的示波页），可以直接看输出和纹波。
  删掉后不会再自动出现（安装内只播种一次）。
- **示例工程是只读的**：名字里带“示例”的工程可以随便看、随便仿真，但一旦你改动
  它（放元件、改参数、连导线…），App 会立刻把当前电路**另存成一个新工程**并切过去
  （例如“MOS 开关板”），原示例文件一个字节都不会变；之后的编辑都保存在这个新工程里。
  想回到原始示例就再打开一次列表里的示例卡片。
- 顶部四个示例按钮（分压 / RC / 555 / MOS 板）同样会创建可运行的示例工程，
  创建后立即自动仿真并打开最有用的结果页；“MOS 板”就是下面那套 12 V PWM 开关 +
  LC 滤波 + 示波器的整板电路。
- 工程的名称、电路和开关状态都保存在应用的内部存储中，编辑时自动保存。
- 删除工程有二次确认。

### 绘制页

画布上方是浮动工具胶囊（选择 / 导线），右下角是缩放与适应按钮，底部操作栏
左侧是启动/暂停仿真，右侧是结果面板和圆形 **+** 添加按钮。

- **添加元件**：点 **+** → 选择分类（基础、电源与信号、半导体、晶体管、
  模拟芯片、数字逻辑、开关与负载、功率与滤波、仪器、接口）→ 点选元件卡片。
  分类和元件由元件目录自动生成，新元件会自动出现在对应分类中。
  卡片列表**可以用手指上下滑动**：按下后只要移动超过约 9 dp 就算“滑动”，
  只滚动列表、不会误选中卡片；真正点选在**抬手指且没有滑动**时才生效
  （首页工程列表和结果面板的滚动区域同样适用）。
- **点一次放一个**：在工作表里选中元件后，点一下画布就把这一个放下去，
  放完自动回到选择状态并把新元件选中（可以直接改参数），要再放一个就再点 **+**。
  放好之前如果改主意，可以点顶部“正在放置”胶囊的 **完成** 取消。
- **元件很小**：电阻、电容、电感、二极管、三极管、电源、开关、灯泡、风扇、制冷片
  这类 2~3 脚元件现在只占 **2 格**（引脚在中心上下各 1 格），图形也跟着缩到半尺寸，
  同一个屏幕上能摆下大约两倍的元件。8 脚/5 脚的芯片（555、运放、逻辑门、7805）
  引脚间距仍是 2 格，但外形也收窄了（555 从 8 格宽收到 4 格宽）。
  **旧工程会自动变小**：打开老工程（文件版本 1）时，导线会被自动搬到新引脚上
  （端点贴新引脚、T 型接头跟随、互相搭在一起的引脚补短线，再重新绕线），搬完之后
  会做一次“连通性自检”——只有当每个引脚仍连在同一个网络上时才保留缩小版；
  万一自检不通过，这个工程会保持原来的尺寸（导线一条都不会断），并弹提示说明。
- **选中只高亮元件本身**：点选元件时不再画一圈外围方框，整个符号变成高亮色
  （损坏的负载是红色），底部弹出参数卡。
- **旋转与翻转**：参数卡右上角有 **旋转**（每次 90°）和 **翻转**（左右镜像）两个按钮，
  两者可以任意叠加：先翻转再旋转，等同于绕着另一个轴转 90°。所以三极管的基极、
  二极管的极性、555 的引脚排布都能摆到需要的方向，而不是只有四种角度。
  元件的引脚会跟着移动，接在引脚上的导线端点也会一起跟过去（不会掉线）。
- **导线**：切到“导线”工具后，**所有可接的接点都会高亮**（元件引脚是空心小圈，
  导线已有接头也是）。点第一个接点开始，再点第二个接点**自动布线**：
  正交走线，**自动绕开途中的引脚、导线接头和其他导线**——导线不会从别的引脚或接头上
  碾过去（那会偷偷连通两个网络），也不会和已有导线叠着走（那会把两个网络并成一条）。
  实在绕不开时才允许垂直穿过（画成跳线拱桥，电气上仍然不相连）。
  **点空白处不会画线**，只会提示“导线只能接在元件引脚或导线接头上”。
- **跳线（交叉但不相连）**：两条导线交叉时，只有端点/接头重合才算连接；如果只是
  两条线**从中间穿过**，就画成跳线——**先放的导线直走，后放的导线在交叉点画一段
  半圆拱桥跨过去**，一眼就能看出没连在一起。桥的凸起方向固定（水平线向上、
  垂直线向右），而且**电子流动动画也会沿拱桥爬过去**，不会从交叉点直穿。
  T 型接头、端点重合仍按真实连接绘制。
- **平移 / 缩放**：未按在元件或导线上时，单指在画布空白处上下左右拖动即可
  平移；双指捏合缩放，缩放以两指中点为中心。右下角的 − / + / 适应按钮也可
  缩放或回到全图。
- **编辑**：点选元件会弹出底部参数卡，可改数值、旋转、删除；开关可直接切换。
  半导体和芯片会显示型号与各引脚电流。PWM 源可改高电平、频率和占空比；
  功率电感/电解电容多一行内阻（DCR/ESR）；陶瓷电容多一行 ESL；示波器卡片直接
  显示平均值与纹波；功率电阻卡片显示**额定功率**和实时功耗（超标会烧断，可修复）；
  灯泡/风扇底部一行是**额定电流和额定功率**（可点可改，与电阻联动），
  制冷片卡片显示冷面温度曲线、制冷量/输入功率/COP，并可以改**初始冷面温度**和
  **冷面热负载**。顶部栏提供撤销/重做和菜单（适应视图、设置、重命名工程）。
- 设置里可以调整瞬态步长（100 ns ~ 1 ms）和停止时间（100 µs ~ 50 ms）；
  含 555 的电路会自动使用足够长的瞬态窗口。含 PWM 等高频信号源（周期 ≤ 200 µs）
  时，窗口会自动扩展到约 1500 个周期（上限 50 ms）、步长细化到周期的 1/20，
  这样既能进入稳态，又能看清开关纹波（示例 50 kHz 时为 30 ms / 1 µs，约 1~2 秒算完）。

### 用输入法输入精确数值

参数卡里每个可调数值后面都有一个**带蓝框的数值按钮**（例如 `4.7 kΩ`、`12.0 V`、
`50 %`）。点它就会弹出数值输入框，并立刻弹起系统输入法，直接键入准确值——
不必再靠拖滑块凑数字。

- **能输入的参数**：电阻/电容/电感值、功率电感的 DCR、电解电容的 ESR、
  灯泡/风扇的电阻与额定/启动/上限电压、电流上限、**额定电流、额定功率**、
  功率电阻的**额定功率**、
  电源的幅值与频率、PWM 占空比、稳压管稳压值、制冷片的**初始冷面温度**和
  **冷面热负载**；设置面板里的**瞬态步长**和**停止时间**也有“键盘输入”按钮。
- **能这样写**：`4700`、`4.7k`、`1k2`（1.2 kΩ）、`4R7`（4.7 Ω）、`100n`、
  `2µ2`（2.2 µF）、`1M`（兆，`1meg` 同义）、`1e-3`、`2.5E3`、`4,7k`（逗号小数点）、
  全角数字 `１２３` 都认；数字后面跟单位（`10 kΩ`、`5 V`、`50%`）也认。
  注意 `m` 是毫、`M` 是兆。
- **前缀按钮**：也可以只键入数字（如 `4.7`），再点 **p / n / µ / m / — / k / M**
  换算单位，同时保留“4.7 kΩ”这种工程写法；输入框里已经带后缀时（如 `4.7k`），
  以后缀为准。
- **确认前看得见结果**：输入框下面实时显示 `= 4.7 kΩ` 和允许范围，数值越界或认不出
  时会给出中文提示并保持弹窗，不会写进电路；点 **确定** 才生效（并进入撤销栈），
  点 **取消** 原样退出。
- **数字键盘**：Android 上通过 SDL 的 `SDL.textinput.android.inputtype` 指定
  “数字 + 小数点 + 负号”的输入类型，所以弹的是数字键盘而不是中英文键盘；
  机型不支持时自动退回系统默认键盘，输入法行为不变（工程命名仍是普通键盘）。

### 半导体制冷片（Peltier）

“开关与负载”分类里有两片半导体制冷片：**制冷片 12706**（TEC1-12706）和
**制冷片 12710**（TEC1-12710）。它们接直流电源就能“制冷”，是真正的电热耦合负载，
不是一个假电阻：

```
V = I·R + α·ΔT            端子电压 = 欧姆压降 + 塞贝克反电动势
Qc = α·I·Tc − I²·R/2 − K·ΔT   冷面净抽热（=0 时达到稳态）
Qh = P + Qc               倒进热面的热量
COP = Qc / P              制冷量 / 输入电功率
```

- **热面固定 20 °C**：模型把热面钉在散热器温度上（20 °C 的铝块永不变热），
  所以冷面能降到多低完全由电功率、反电动势和漏热决定。
- **冷面温度是算出来的**：冷面有一个热容和一个到热面的热导，用仿真跑出来。
  12 V 驱动 12706、冷面热负载 0 W 时：稳态冷面 **−42.7 °C**、温差 62.7 K，
  电流从刚上电的 6.06 A（冷态，ΔT=0）一路降到 4.38 A（反电动势顶住了电压），
  输入功率约 53 W。5 V 只能到 −15 °C 左右，电压不够就压不下去。
- **冷面热负载**：实际用的时候冷面贴着要散热的东西，那点热量会漏回来。参数卡的
  **热负载**（0–100 W）就是把这份热量加到冷面上：8 W 时 12706 只能到 −33.7 °C，
  12710 大约 −37.6 °C（它电流更大、内阻更小）。
- **降温过程**：瞬态分析里冷面从**初始冷面温度**（默认 20 °C，可改成 −20 °C
  模拟先预冷过的板子）开始下降，参数卡底部画出冷面温度曲线，白线是热面 20 °C，
  曲线落在下面就是“比环境冷”。这样的“一次性”过程**播放一遍就停在稳态**，
  不会像 PWM/正弦那样循环播放、让温度看起来又跳回初始值；改参数重新仿真时会
  从头再播一次。真实的一块 12706 冷面热容约 15 J/K，光稳定就要
  一分钟；模型把热容缩小到 1/1700 左右，于是**同一个降温过程被压缩进 30 ms 的
  瞬态窗口**——温度数值是真实的，时间轴是加速的。
- **极性反了会制热**：模块是双向的。电流反过来时同一个冷面变成发热面（卡片和
  电路图上的箭头/配色都会翻过来），可以用来演示“接反了会烧东西”。
- **损坏**：超过数据手册的 Vmax（15.4 V）就会过压损坏（显示为开路，可**修复**）。
  电流上限放宽到 1.35×Imax，因为冷态的模块上电瞬间电流本来就偏大
  （12 V 时 6.06 A > Imax 6 A），稳态超限才真正危险。
- **注意**：制冷片必须接直流电源；它自带瞬态过程，所以含制冷片的电路会自动跑
  瞬态分析（窗口至少 50 ms），否则只跑工作点就看不到降温曲线了。
- 首页“我的工程”里预置了一个 **制冷片示例 TEC1-12706**（12 V 电源 + 一片 12706，
  冷面热负载 8 W），打开后按“启动仿真”就能看到冷面一路降下去。

### 仿真

底部左侧是 **启动仿真 / 暂停仿真** 按钮：

- 只有启动后才会运行 ngspice 并显示支路电流。
- 纯直流电路运行工作点分析；含交流/正弦/方波电源或 555 定时器时自动运行瞬态分析。
- 启动后修改电路或切换开关，会在短暂防抖后自动重新仿真。
- 灯泡/风扇有真实的额定参数：**额定电压**（满亮/满转）、**启动电压**（低于它
  不亮/不转，参数卡显示“欠压未启动”）、**最大电压**（风扇默认只允许 +10 %，
  即常见的“超频 10 %”；灯泡 +15 %）、**电流上限**。超过上限即**损坏**（显示为
  开路，可能是过压或过流）；损坏是可恢复的，重新启动仿真或修改参数/电路后恢复。
- 画布上显示两脚元件的电流（数值 + 方向箭头）；三极管、MOS 和芯片在选中后
  的参数卡里按引脚显示电流（如 Ic/Ib/Ie、555 各脚）。导线上有电子流动效果，
  沿整条回路连续移动（跨导线接头和元件），方向由电流方向决定，
  速度随电流大小变化。
- 灯泡按电压平方（电功率）发光，风扇按电压算转速，LED 按正向电流发光。
  灯泡画成真实灯形
  （玻璃壳 + 灯丝 + 螺口），LED 同理；它们的**光晕在所有元件之后绘制**，
  所以灯光会盖在导线和相邻元件上，不会被压在下层。光晕由 3 层同心圆叠加
  （半径约 3.1 / 2.05 / 1.3 格，亮度随负载电压变化），缩到全图也能一眼看出
  哪只灯泡亮着。
- **导线和元件在视觉上分开**：导线用独立的铜绿色（`#48b27a`）、线宽 2.0 dp，
  元件符号用亮白色、线宽 2.6 dp；导线的接头圆点也改成同色小点，
  接点标记进一步调暗，扫一眼就能分清"铜"和"器件"。
- **开关电源的动画取平均**：一个窗口里包含几十个以上开关周期时（例如 50 kHz、30 ms），
  播放时每帧会跳过好几个周期，直接显示瞬时电流会让电感、二极管、输入电容这些支路的
  电子方向每帧乱跳。此时画布上的电子流动和读数会**按一个开关周期取平均**，
  显示的是真正有意义的直流流向；瞬时波形仍可在“波形 / 示波”页查看。
  低频电路（如 100 Hz 的 RC 示例）不受影响，依旧是瞬时值。
- 右下角“结果”打开面板：
  - **电流**：各元件电流表；多引脚元件的每个引脚单独一行。
  - **电压**：节点电压；瞬态时按当前播放时刻显示。
  - **波形**：节点电压随时间变化，可勾选节点。
  - **示波**：每个示波器探头的差分波形 + 稳态数字（平均值 / 峰峰纹波 / 纹波占比 /
    有效值 / 开关频率）。时间窗可在“全程 / 稳态（最后 5%）/ 纹波（约 2 个开关周期）”
    之间切换；多个探头可分别勾选。
  - **网表**：生成的 SPICE 网表，可复制。
  - **日志**：ngspice 输出与错误原因。日志框可**长按拖动选择文本**，
    下方有“复制日志”（一键全选复制）和“复制选中”两个按钮；
    编译期错误（接错线、元件没接、电源短路/并联）也会写在这里。

## 架构

```
Android SDLActivity
  └─ libSDL3.so + libmain.so (SDL_main)
       ├─ ui/        SDL3 + Dear ImGui（首页、工程、编辑器、参数、结果、波形）
       ├─ core/      Circuit / Netlist / NgspiceEngine / ProjectIO
       └─ libngspice.so（从源码交叉编译）
```

- `core/` 不依赖 SDL/Android；同一套代码被 APK 和 `engine_tests` 使用。
- `core/ComponentCatalog` 集中定义元件分类、引脚布局、SPICE 家族和显示名；
  元件库、画布、网表和存档都从同一份目录读取。
- `core/SpiceModels` 存放自写的 `.model` 和 `.subckt` 文本（无第三方厂商模型）。
- 节点提取使用 union-find，支持任意数量和位置的引脚，以及引脚在导线内部、
  导线端点在另一条导线内部的 T 型连接。导线是多段折线（自动布线可能给出好几个拐角）。
- `core/Router` 负责自动布线：在网格上做带转角代价的最短路径搜索，
  把引脚、导线接头当作硬障碍（碾过去就等于连通），把和已有导线重叠的走向也当作
  硬障碍（重叠会并网），把跨过别的导线当作高代价（画成跳线，电气上不相连），
  把压在元件身上当作中代价（尽量不压）。
- 电子流动画使用 `core/Flow`：导线在引脚和接头处切成小段，按每个节点的
  电流守恒求解各段电流；两脚元件一条器件边，多脚元件每脚一条“引脚→中心”
  边；粒子沿电流方向在段与段之间连续转移，因此不直接接触元件的导线同样有
  电子流动。
- ngspice 调用串行化；所有仿真在 `std::async` 工作线程执行，UI 轮询结果，不阻塞触摸。
- 切换工程时会使在途仿真结果失效，避免旧工程的电压/电流泄漏到新工程。
- 字体为 OFL 许可的 Noto Sans SC 子集（`android/app/src/main/assets/fonts`）。
  ImGui 1.92 使用动态字形图集，按需加载实际出现的字形；新增中文文案无需重新生成范围表。

## MOS 开关板：12 V PWM → 恒压输出

目标板子：6 个接口（信号 + 地、DC 12 V 入、输出），在常规 MOS 开关板上加电容、
电感，用 50 kHz PWM 把 12 V 方波“直接”变成恒压输出。首页“MOS 板”示例就是这套
电路的完整仿真工程，打开后按“启动仿真”，再看 **结果 → 示波**。

### 布局

示例按功能分成四块、留足间距：左边是“电源 + 源内阻 + J1 端子 + 输入电容”，
左下是“J2 信号端子 + PWM 发生器 + 基极电阻 + NPN”，中部是“高边 P-MOS + 肖特基 +
电感”，右侧是“输出电容 + 灯泡负载 + 探头 + J3 端子”，顶部 12 V 轨、底部地轨贯通。
控制线（PWM、栅极）后画，因此它们跨过输入电容/二极管的地线、以及开关节点线时
会自动画成四处跳线拱桥。

### 拓扑（示例即为该拓扑）

```
                 (板外)                     (板内)                        (板外)
 V1 12V ─[R1 0.2Ω]─┬─ J1 ──┬──── 12 V ──[ M1 功率 P-MOS 高边 ]──┬──[ L1 100µH/60mΩ ]──┬── J3 OUT(+)
  源内阻/线阻      │       │                                   │                     │
                 [C1 100µF/0.15Ω]                        [ D1 肖特基 ]         [ C2 220µF/0.12Ω ]
                   │       │                                   │                 [ C3 100nF ]
                   │       │                                   │                 [ R4 12V 灯泡 ]
                   │       │                                   │                     │
 GND ──────────────┴───────┴───────────────────────────────────┴─────────────────────┴── J3 OUT(−)

                  (板外)                     (板内)
 V2 PWM 3.3V ── J2 ──[ R2 1kΩ ]── Q1(NPN 反相) ──┬── M1 栅极
                                                  R3(330Ω 上拉到 12 V)

 SC1：示波器探头，固定在输出上（开路端直接跨接 OUT+/OUT−）
 SC2：第二只示波器，GND 夹已接板内地，CH1 **空着**，自己拉线接到任意节点测量
```

名称与工程里一致：**J1** 12 V 输入端子、**J2** PWM 信号端子、**J3** 输出端子；
**V1** 12 V 电源、**R1** 0.2 Ω 电源内阻/线阻、**C1** 100 µF 输入电容；
**V2** PWM 发生器（3.3 V，模拟单片机）、**R2** 1 kΩ 基极电阻、**Q1** NPN 反相、
**R3** 330 Ω 上拉、**M1** 功率 P-MOS、**D1** 肖特基续流、**L1** 100 µH、
**C2/C3** 220 µF + 100 nF 输出滤波、**R4** 6 V / 6 W 灯泡负载（额定 1 A，
3 V 起亮，9 V 以上才烧毁，正好容纳启动时 8 V 的过冲）、
**SC1/SC2** 示波器探头。

- PWM 为高 → NPN 导通 → P-MOS 栅极被拉低 → 高边开关导通，开关节点 = 12 V。
- PWM 为低 → NPN 截止 → R2 把栅极拉到 12 V → Vgs ≈ 0 → P-MOS 关断，电感电流经
  D1 续流，开关节点 ≈ −0.4 V。
- 所以输出 = **占空比 × 12 V**（再扣掉二极管、导通电阻和 DCR 的损耗），
  纹波由 L、C、ESR 和频率决定。

### 为什么不用“低边 N-MOS + LC”

低边 N-MOS 只能把节点拉到地，关断时电感电流没有释放路径，节点会被抬到 12 V 以上
（升压式过冲），滤波后得不到干净的直流。要得到平滑的恒压输出，开关必须接在 12 V
一侧（高边），并且必须有续流二极管——这也是示例里用 P-MOS 而不是 N-MOS 的原因。
如果一定要用低边 N-MOS，就必须改成“输入 → 电感 → 开关节点 → 负载”的回流式结构，
或者干脆用带自举的高边驱动。

### 常见错误：电源被接“短路”了

给 J1 加外部 12 V 时，如果电源被旋转成**水平**再丢到一条导轨上，它的两个引脚会同时
落在同一条线（12 V 轨或地轨）——等于用理想电压源短路自己，ngspice 只会回一句
`Fatal error: instance v3 is a shorted VSRC`。现在引擎会先拦下来并说明：

```
元件 V3 的两端接在同一个节点上（电压源被短路）。
请把它的两端分别接到不同的网络：+ 接电源轨或负载，− 接地。
```

正确接法：**+ 脚**落在 J1 的 1 脚（12 V 轨），**− 脚**落在板内地（J1 的 2 脚）。

还有一种常见情况是**元件放上去但没接线**：理想电压源只要有一端没接，它就构成一个
“浮空孤岛”，ngspice 会直接中止整个瞬态分析。现在会点名：

```
元件 V3（直流电源）没有接到电路上（所在的网络没有通向地 GND 的通路），
理想电源悬空时无法仿真。请把它接到要供电的位置，或者删掉它。
```

（只由无源件组成的浮空孤岛不会报错，ngspice 靠 gmin 能自行处理。）
同理，两个理想电压源直接并联也会被拒绝，并提示删掉一个或串一个小电阻；
浮空节点、被电容隔断的节点、步长过小导致推进不下去的情况也会给出中文提示
（见“结果 → 日志”）。

### 50 kHz 下的经验值

- 电流纹波：`ΔI = (Vin − Vout) · D / (L · f)`，示例 = 6 V × 0.5 / (100 µH × 50 kHz) ≈ 0.6 A。
- 电容纹波（三角近似）：`ΔVc = ΔI / (8 · f · C)` ≈ 6.8 mV；ESR 纹波 `ΔI · ESR` ≈ 72 mV。
  所以 220 µF 电解电容的纹波几乎是 ESR 决定的，想更小就并联低 ESR 电容。
- 空载/轻载时 LC 二阶滤波器的 Q 值很高（`Q = R·√(C/L)`），启动会有一段低频振铃，
  需要足够长的瞬态窗口（示例 30 ms）；示例输出约 5.84 V、纹波约 72 mV（50 kHz），
  灯泡负载上约 0.97 A（6 V / 6 W 灯泡点亮到约 90 %）。
- 想自己量别处（开关节点、栅极、电感电流后的输出）：拖动 **SC2** 的 CH1 到目标节点
  即可，示波页会多出一条曲线和一组数字；仪器分类里也能随时再加示波器元件。
- 占空比越大输出越高，但栅极驱动速度、二极管压降和导通损耗都会让实际值偏离
  `D × Vin`，仿真里可以直接读到偏差。

## 首版限制

- 仅 `arm64-v8a`；未做 release 签名。
- 不支持 AC 扫描/FFT，也没有环路稳定性（交流小信号）分析；开关纹波靠瞬态仿真读值。
- 瞬态点数上限 200000（示例 50 ms / 1 µs = 5 万点）；功率器件是简化 LEVEL=1 模型，
  不含热模型、饱和电流和实际封装寄生参数。
- IRL540N 用 ngspice 的 LEVEL=1 MOS 模型：只拟合了阈值电压和导通电阻，
  没有击穿电压、栅极电荷、结电容和热模型，所以开关损耗、米勒平台这些看不到；
  陶瓷电容只有 C/ESR/ESL 三个参数，没有直流偏压/温度导致的容量衰减。
- 制冷片用**单节点热模型**：只算冷面温度，热面永远 20 °C（没有散热器热阻、
  没有热面升温），α/R/K 不随温度变化，冷面热容按约 1/1700 压缩以便在 30 ms
  窗口里看到降温过程。真实模块还有接触热阻、结露、低温下 α 下降等效应。
- 半导体和芯片使用自写的简化/行为模型：二极管、三极管、MOS 的模型参数固定，
  运放、逻辑门、555 和 7805 是功能模型而不是厂商工艺模型；不做器件型号库。
- 开关用电阻近似（1 mΩ / 1 GΩ），灯泡/风扇用负载电阻建模，不是完整的物理模型。
- 自动布线只在起点/终点附近有限范围内搜索（最多 160×160 格），绕不过去时会退回
  直角连接；导线不能被拖动调整形状，也不支持一次连多个接点。
- 没有系统文件选择器/分享；工程保存在应用内部存储，网表可复制。
- 数值既可以拖滑块（另有 ÷10 / ×10 步进），也可以点数值按钮用输入法输入精确值，
  见上文“用输入法输入精确数值”；两种方式共用同一套取值范围与钳位规则。
  数值范围是软限制：超出范围会提示并拒绝写入，而不是静默截断。

## 依赖与构建

```bash
./scripts/fetch-deps.sh              # 拉取 SDL3 / Dear ImGui / ngspice 源码
./scripts/build-ngspice-android.sh   # 交叉编译 libngspice.so（arm64-v8a）
./scripts/build-apk.sh               # 生成 APK 到 dist/
./scripts/install-apk.sh             # 通过 adb 安装到真机
./scripts/run-engine-tests.sh        # 跑无头引擎测试
```

`third_party/` 与 `android/app/src/main/jniLibs/` 都不入库：前者由脚本下载，
